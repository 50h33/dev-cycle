# 이슈 작성

아직 시작하지 않은 응집된 작업을 저장소 템플릿에 맞춰 이슈로 정리합니다. 이미 완료된 작업을 사후 기록하는 요청이라면 그 차이를 알리고 사용자의 의도를 확인합니다.

공통 브랜치·GitHub 표기·외부 작업 규칙은 [`AGENTS.md`](../../../AGENTS.md)를 따릅니다.

## 규칙

- 이슈를 작성하는 동안 제품 코드를 수정하지 않습니다.
- [`.github/ISSUE_TEMPLATE/`](../../../.github/ISSUE_TEMPLATE/)에서 작업 성격에 맞는 템플릿을 선택합니다.
- 대화와 확인한 저장소 상태에 근거해 범위와 완료 조건을 씁니다. 필요한 정보가 결과를 크게 바꿀 때만 질문합니다.
- 관련 작업을 지나치게 잘게 나누지 않습니다.
- 이슈 게시, 라벨·담당자 변경, 의존 관계 설정 같은 외부 변경은 사용자가 요청한 범위에서만 수행합니다.

## 작성 절차

1. `$ARGUMENTS`와 대화에서 배경, 작업 범위, 제외 범위, 완료 조건을 정리합니다.
2. 템플릿의 질문을 본문 제목으로 사용하고 필수 항목을 채웁니다.
3. 제목에는 작업 내용을 간결하게 쓰고, 템플릿의 `labels` 값과 맞는 라벨을 선택합니다.
4. 게시 전에 `gh repo view --json nameWithOwner -q .nameWithOwner`로 현재 저장소를 확인하고 `gh label list`로 라벨 존재 여부를 확인합니다. 없는 라벨은 만들지 않고 생략 사실을 보고합니다.
5. 사용자가 게시를 요청했다면 `gh issue create --title "..." --label <label> --assignee @me --body-file <file>`로 생성합니다. 저장소가 지원하는 Issue Type이 확인되고 요청 범위에 포함된 경우에만 타입을 지정합니다.

선행 관계가 명확하더라도 사용자가 관계 설정까지 요청하지 않았다면 본문에 관련 이슈만 기록합니다. GitHub 의존 관계나 코멘트는 별도 외부 변경으로 취급합니다.

## 결과 보고

- 선택한 템플릿과 이유
- 제목, 라벨, 본문 또는 생성된 이슈 URL
- 생략하거나 확인하지 못한 메타데이터
- 작업을 시작할 때 사용할 `{라벨}/{이슈 번호}` 브랜치 이름

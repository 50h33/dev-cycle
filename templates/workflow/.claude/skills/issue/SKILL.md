# 이슈 작성

저장소 루트의 `dev-cycle.config.json`에서 `repository`, `paths.issueTemplates`, `paths.conventions`를 읽는다.

## 규칙

- 제품 코드를 수정하지 않는다.
- 설정된 이슈 양식을 읽고 필수 항목을 본문에 반영한다. 양식이 없으면 확인된 배경, 범위, 제외 범위와 관찰 가능한 완료 조건으로 작성한다.
- 대화와 저장소에서 확인한 사실만 사용한다. 사후 작업을 앞으로 할 일처럼 쓰거나 미실행 검증을 완료로 표시하지 않는다.
- 게시, 라벨/담당자 변경, 하위 이슈와 의존 관계는 사용자가 요청한 외부 변경 범위에서만 수행한다. 이미 그 범위를 승인했다면 다시 묻지 않는다.

## 절차

1. 요구사항 기반 작업인지 완료된 작업의 기록인지 구분한다.
2. 저장소와 템플릿을 확인하고 작업 성격에 맞는 양식을 고른다. 열린 이슈와 닫힌 이슈를 확인해 중복 작업은 기존 이슈를 재사용한다.
3. 제목, 라벨, 본문과 필요한 관계를 초안으로 만든다.
4. 게시가 요청됐다면 설정의 `repository`와 실제 현재 저장소가 일치하는지 확인한 뒤 생성한다. 저장소가 지원한다고 확인한 메타데이터만 설정한다.
5. 생성 후 이슈를 다시 조회해 제목, 본문, 라벨과 관계를 확인한다. 요청 실패나 응답 불명확 시 생성 여부부터 조회하고 중복 생성하지 않는다.

## 보고

선택한 양식과 이유, 제목과 라벨, 본문 또는 URL, 생략한 메타데이터와 검증 결과를 보고한다.

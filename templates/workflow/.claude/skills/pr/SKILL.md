# PR 작성

저장소 루트의 `dev-cycle.config.json`에서 `repository`, `defaultBranch`, `baseRef`, `paths.prTemplate`, `paths.conventions`를 읽는다.

## 규칙

- 현재 브랜치가 기본 브랜치이거나 기준 ref 이후 커밋이 없으면 게시하지 않고 상태를 보고한다.
- 기준 ref의 커밋과 diff, 대화에서 확인된 결과만 적는다.
- 테스트에는 실제 명령, 종료 상태와 해당 실행에서 확인된 결과만 쓴다. dry-run, `PreToolUse` 로그와 과거 결과를 통과로 바꾸지 않는다.
- 테스트 시점과 현재 HEAD, staged/unstaged/untracked 내용을 대조한다. 테스트 뒤 코드가 바뀌었거나 같은 상태인지 확인할 수 없으면 다시 검증하거나 “현재 코드 미검증”을 표시한다. 이전 통과는 과거 결과로만 구분하며 PR 게시 승인을 테스트 성공으로 해석하지 않는다.
- dev-cycle CLI report가 실제로 설치돼 기록 기반 초안을 만든 경우에만 이를 사용한다. 아직 없으면 수동으로 확인된 결과를 기록한다.
- push, PR 게시, 라벨과 리뷰어 지정은 사용자가 요청한 범위에서만 수행한다. 이미 승인된 게시 요청은 반복 확인하지 않는다.

## 절차

1. 현재 브랜치, 작업 트리, 기준 ref 이후 커밋과 diff를 확인한다.
2. 관련 이슈와 설정된 PR 양식을 읽는다.
3. 실제 변경과 검증으로 제목과 본문을 작성한다. 수행하지 못한 검증은 이유를 적는다.
4. 게시가 요청됐다면 설정의 저장소와 base를 다시 확인하고 필요한 push와 PR 생성을 수행한다.
5. 생성된 PR을 다시 조회해 head, base, 제목, 본문과 메타데이터를 검증한다.

## 보고

제목, base, 라벨, 리뷰어와 담당자, 본문 또는 URL, 실행한 검증과 남은 상태를 보고한다.

# 리뷰 반영

저장소 루트의 `dev-cycle.config.json`에서 `repository`, `paths.conventions`와 프로젝트 명령을 읽는다.

## 규칙

- 현재 브랜치와 PR head가 일치하는지 먼저 확인한다.
- 코멘트의 diff 라인을 그대로 믿지 않고 현재 PR head 파일과 대조한다.
- 해결된 스레드와 후속 답글을 중복 처리하지 않는다.
- 코멘트 범위를 벗어난 리팩터링을 하지 않는다.
- 사용자가 이미 수용/거절 범위를 지정했다면 수용 항목을 바로 수정하고 검증한다. 판단이 남은 항목만 질문한다.
- push, 답글과 resolve는 요청된 외부 변경 범위에서만 수행한다. 원격에서 확인할 수 없는 커밋 링크를 게시하지 않는다.

## 절차

1. PR 메타데이터와 현재 브랜치를 비교한다.
2. 모든 페이지의 리뷰 스레드와 코멘트를 조회하고 해결된 스레드를 제외한다.
3. 루트 코멘트별로 수용, 거절, 보류를 분류하고 근거를 제시한다.
4. 수용 항목을 현재 코드와 다시 대조해 좁게 수정한다.
5. 검증은 `/test`의 Git 루트와 인자 전달 규칙을 따라 실제 결과를 기록한다. 그 밖의 프로젝트 명령도 같은 실행 규칙을 적용한다.
6. 답글이 요청됐다면 확인 가능한 변경만 설명한다. resolve는 명시된 스레드에만 수행한다.

## 보고

코멘트별 분류와 근거, 변경 파일, 실제 검증 결과, 커밋/push/답글/resolve 수행 여부와 보류 사유를 보고한다.

# /test - 변경 영향 테스트

변경된 범위의 테스트를 실제로 실행하고 확인된 결과만 보고한다.

## 실행

1. `git rev-parse --show-toplevel`로 Git 루트를 확인하고 그 루트의 `dev-cycle.config.json`에서 `baseRef`, `commands.test`, `test.commonModules`, `test.fullTestPaths`, `test.documentationPaths`, `artifactsDir`를 읽는다. 루트를 확인할 수 없으면 실행하지 않는다.
2. 설치된 CLI의 `dev-cycle test --dry-run --json`으로 선택 대상과 이유, 실행할 명령을 확인한 뒤 `dev-cycle test --json`으로 실행한다. dry-run에서는 저장소를 변경하지 않는다. ref 오류나 미지원 설정을 만나면 임의 명령으로 우회하지 않는다.
3. CLI가 아직 없으면 Git 루트를 작업 디렉터리로 지정하고 등록된 프로젝트 테스트 명령을 직접 실행한다. 설정의 `executable`과 `args`를 유지하며 Windows 변형이 있으면 둘 다 해당 값으로 대체한다. 실행 도구가 argv 배열을 받으면 그 인터페이스를 사용한다. Bash처럼 shell 문자열을 받는 도구에서는 실제 shell의 인용 규칙을 확인하며 설정값을 단순 연결하거나 eval하지 않는다. 특히 Windows 배치 파일과 메타문자 인자의 정확한 전달을 확인할 수 없으면 실행하지 않고 미실행 이유를 보고한다.
4. 실제 종료 코드, 실행한 인자, 시작과 종료, 테스트 전후의 HEAD와 staged/unstaged/untracked 변경, 확인된 테스트 결과를 보고한다. 실행 중 코드가 바뀌었으면 안정된 한 코드 상태를 검증했다고 표시하지 않는다.
5. PR 검증 블록이 필요하면 테스트가 저장한 `recordPath`를 기준으로 `dev-cycle report --json`을 실행한다. report가 없거나 실패하면 수동으로 확인한 결과만 사용한다.

## 상태 구분

- 성공: 실제 프로세스가 끝났고 해당 실행의 성공 증거가 있다.
- 실패: 비정상 종료 또는 해당 실행의 실패 결과가 있다.
- 중단: 취소나 신호로 실행이 끝나지 않았다.
- 생략: 문서 변경 등 명시된 규칙으로 실행하지 않았다.
- 미실행: dry-run, 실행 파일 없음, 설정 오류 등으로 시작하지 않았다.

`PreToolUse` 로그, 이전 결과 파일, 명령 문자열을 본 사실만으로 성공을 표시하지 않는다. CLI의 `recordPath`, `execution`, `evidence`, `codeState`를 확인한다. 실행 전후 코드가 달라지거나 이후 변경이 있으면 현재 코드 미검증으로 보고한다. 코드를 수정하거나 커밋과 push를 수행하지 않는다.

설정 검사와 JSON 렌더링 통과는 실제 프로세스 실행이나 인자 전달 검증이 아니다. CLI가 지원하는 정적 Gradle 문법과 루트 Wrapper, 허용 옵션 및 Windows 경로 제한을 확인한다. CLI가 없는 환경의 직접 실행 결과에는 CLI 지문이나 기록이 있다고 주장하지 않는다.

프로세스의 성공 종료와 실제 테스트 실행을 구분한다. 캐시, UP-TO-DATE, NO-SOURCE 또는 테스트 0개를 새 테스트 통과로 표현하지 않는다. CLI가 없어서 코드 내용 지문을 남기지 못했다면 이후 같은 코드임을 단정하지 않고, PR 작성 전에 재실행하거나 현재 코드 미검증으로 보고한다.

report는 저장된 합계와 상태를 표현할 뿐 테스트를 다시 실행하지 않는다. 최신 실패/중단 기록을
과거 성공으로 대체하거나 V1 기록에 없는 실패 테스트 이름, 커버리지와 CI 결과를 추측하지 않는다.
